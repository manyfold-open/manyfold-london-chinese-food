## 一句话

把一本"可信但严肃"的中餐目录，包装成在英华人每天都想打开的**伦敦干饭地图**：用伦敦地铁图的语言画中餐，用真实发生的核实、原话和价格制造热闹，不靠评分和假数字。

## 1. 现状诊断

**内容其实很厚，只是没被"演"出来。**

| 资产 | 线上数量 | 现在怎么呈现 |
|---|---|---|
| 店铺 | 1,625 家（1,559 家在营业），33 个菜系标签 | 筛选 + 列表 |
| 原话摘录 | 2,557 段，中英双语，来自 Time Out、The Infatuation、红领巾、Dealmoon 等 | 藏在店铺页第二个 tab |
| 菜单菜品 | 143,575 道，大多带价格 | 店铺页里的长列表 |
| 标准菜名 | 15,972 个，可以跨店比价 | 只有搜索时出现 |
| AI 示意图 | 520 张，已审核 | 菜单缩略图 |
| 实拍 | **7 张，只覆盖 1 家店** | 几乎看不到 |
| AI 采集员与核实员 | wok-scout-london、dumpling-scout、GPT-6 luna、gemini-02 等，每家店的公开档案里都有名字 | 档案 tab 里的英文日志 |

问题不在数据，在表达：

1. **没有"今天"**：首页每次打开都一样，感觉不到有人在持续更新。
2. **没有"人"**：采集员、核实员、写原话的媒体和博主，都藏起来了。
3. **没有场景入口**：留学生想的是"学校附近 £10 吃饱"，不是"选择菜系标签"。
4. **视觉是工具，不是生活**：白底细线一点红，适合后台，不适合被转发。

**硬约束**（来自 AGENTS.md，改版不能碰）：不打分、不按评论数排序、没有聚合分（铁律 17）；只公开已核实的记录（铁律 1）；AI 示意图必须标注、不能顶替实拍（铁律 18）；只署公开作者的名字（铁律 23）。所以"热闹"不能靠星级、热门榜和"xx 人看过"。

## 3. 定位与品牌

**名字**：主标「伦敦干饭地图」，英文保留 London Chinese Food。"干饭"是留学生的日常用语，"地图"说清用途，也覆盖"伦敦 中餐 地图"这类搜索。备选：伦敦中餐地图、干饭伦敦、伦敦觅食线。

**视觉语言：伦敦地铁图。**

- 8 条"线" = 8 组菜系，全部在**唐人街**换乘：点心线（粤菜、早茶、烧腊）、外卖线（英式中餐）、粉面线、奶茶线（奶茶、甜品、烘焙）、北方线（西北、东北、北京、新疆，借 Northern line 的谐音）、麻辣线（川湘渝、火锅、麻辣烫）、新派线、中超线。
- 每个在伦敦的华人每天都坐地铁，看一眼就懂；它是伦敦独有的符号，避开了"中餐 = 红金灯笼"的俗套。
- 组件全部从地铁系统长出来：站牌式店名、线路徽标、到站屏（实时动态）、按步行顺序的"路线"专题。

**色彩**：暖白纸底 + 深墨蓝文字 + 8 条线路色（OKLCH 重调的伦敦线路色）+ 品牌红（与麻辣线同色）+ 到站屏的琥珀色。线路色是功能色：菜系、专题封面都按线着色。

**字体**：标题用一个字体栈，汉字走站酷庆科黄油体（招牌感、有点皮），英文和数字走 Fredoka 窄体（字身窄、笔头圆、笔画均匀，和站酷同一种形态）；正文思源黑体，英文正文和价格表用 Archivo；到站屏的时间用 DotGothic16 点阵体。

**语气**：像会吃的学长学姐，不像官网。"今天在伦敦吃小笼包吗？"、"79 家，0 张实拍，你吃的那一笼可以是第一张"、"只数被提到几次，不代表好不好吃"。标题里不用"最好吃、必吃、排行"，用"最便宜、最近、多少家有、谁写过"。

## 4. 热闹感从哪里来（全部是真的）

| 机制 | 数据来源 | 状态 | 守住的规则 |
|---|---|---|---|
| **实时到站屏**：菜单核对、新原话、新收录、示意图通过、首拍 | 已核实的 revision | 需新增 activity 数据集 | 只播已核实事件，待审内容永不出现（铁律 1、15） |
| **值班采集员**：AI 采集员和核实员的名字、分工、件数 | 店铺档案里的 `by`、token 的 standing | 名字已公开；件数需新增数据集 | 只用公开过的 token 名 |
| **"N 个来源写过它"** + 按年份的原话分布 | reviews | 已有 | 只展示，不参与排序（铁律 17） |
| **价格事实**："79 家有小笼包，£4.80 起，一半不超过 £6.80" | 菜单价 | 已有，需在数据集里预算好统计 | 价格是事实，不是评分 |
| **原话墙**：红领巾、Dealmoon 的中文原话，英文原话的译文 | reviews | 已有 | 只署媒体和公开作者（铁律 23） |
| **点亮伦敦**：1,559 家店的点阵，有实拍的亮起来 | photos | 已有，需活动页 | 照片重新编码、审核前不可见（铁律 19、20） |
| **全站在线人数**："36 人在逛" | 新统计 | 需新增 | 只做全站，不做单店 |

**刻意不做的**：星级和评分、热门榜、按评论数排序、单店浏览量或"想吃人数"、"xx 人刚刚看过这家店"、任何编造或灌水的数字。这些违反铁律 17，也会毁掉这个站最值钱的东西：可信。

## 6. 运营方案

| 时间 | 栏目 | 生产方式 |

| 每天 | 今日一道菜 | 自动：从有示意图、有价格、10 家以上有的标准菜里轮换 |

| 每周三 | 攻略专题 | 编辑：一段导语 + 一个筛选，乘以学校数分发 |

## 7. 要新增的技术能力（不碰铁律）

1. **activity 数据集**：由 `src/worker/docs.ts` 在 cron 里从已核实的 revision 生成最近 N 条公开事件，前端读一行（铁律 15）。不含待审、驳回、撤回。进 `tests/budget.test.ts`。
2. **crew 数据集**：每个 token 的公开名和已核实件数，从 standing 表读（铁律 16 已经保证一类一行）。
3. **菜品价格统计**：在浏览器里用现有的 `/api/dishes/:key` 算店数、最低价、中位价、最高价，不加表。
4. **学校与车站表**：放 `src/shared/`（两个运行时都能用），距离和步行时间在浏览器里从 index 算。
5. **专题配置**：编辑内容，不是 record。每期 = 导语 + 存好的查询；导语过 `rating-guard`（铁律 17）。
6. **全站在线人数**：Durable Object 或 Workers Analytics Engine，不用 cookie，隐私页同步说明。
7. **专题和菜品的分享长图**：浏览器端画布生成，只含公开内容，链接一律经 `publicUrl`（铁律 21）。
8. **字体**：Fredoka、站酷庆科黄油体、DotGothic16 自托管，站酷按字符范围切片，满足现有 CSP（`font-src 'self'`）。
9. **SEO**：线路页、学校页、专题页、菜品页可被索引；页面数据里依然没有 `aggregateRating`。

## 8. 指标

- **北极星**：每周"找到一家店"的访客数（搜索或浏览 → 店铺页 → 点地图、电话或网站）
- **回访**：7 日回访率
- **传播**：分享长图生成数、分享链接带回的访问
- **社区**：每周实拍上传数和通过数（第一季目标：3 个月点亮 300 家），访客建议的新店数
- **内容**：专题读完率、学校版专题的分校访问

## 10. 风险

- **TfL 商标**：不用圆标、Johnston 字体、"Underground"字样和官方线路名；线路名全部自起，只借颜色语言。
- **娱乐化伤害可信度**：出处、日期、"不打分"在每一屏都看得见；专题标题守住"最便宜、最近、多少家有"的用词。
- **AI 示意图太多显得假**：标注不变；用"首拍"机制逐步替换；保留"显示 AI 示意图"开关。
- **到站屏冷场**：夜里事件少时显示"今天已核实 N 条"，绝不补假事件。
- **中文字体体积**：展示字体只用于标题，按需子集化。

## 11. 双语（中 / EN）

**英文读者是谁**：在英国长大、更习惯读英文的华人；想吃正宗中餐的本地人；不讲中文的国际学生和游客。他们要的信息一样，口吻和排版不一样。

**原则：信息不变，文案重写。**

| 中文 | 英文 | 为什么 |
|---|---|---|
| 伦敦干饭地图 | London Chinese Food · THE EATING MAP | 英文主名不变，利于搜索；中文名做副标 |
| 今天在伦敦吃小笼包吗？ | Fancy some xiaolongbao tonight? | 英式口语，菜名用拼音写法 |
| £10 吃饱指南 | Full for a tenner | tenner 是英式口语里的十镑 |
| 一秒回国 / 奶茶续命 | Taste of home / Bubble tea run | 意思对上，不硬译网络用语 |
| 同一站下车 | Same stop | 保留地铁比喻 |
| 点心线、北方线 | Dim Sum Line、North Line | 不用 TfL 的 Northern line |

**规则**

1. **同页互跳**：/zh/ 与 /en/ 一一对应，切换语言停在同一页，页面带 hreflang。
2. **原文优先**：原话展示原文；另一种语言只显示数据库里已有的译文，并标"译 / Translated"；没有译文的原话不出现在另一种语言里。原话一律逐字照录，截短只用省略号。
3. **菜名**：中文版中文名在前；英文版英文名在前、中文名用展示字体跟在后面。英文版的菜品页多一张 **Show the staff** 卡片：大字中文加拼音，点菜时指给店员看。
4. **字体**：标题在两种语言里是同一种形态：汉字用站酷庆科黄油体，英文和数字用 Fredoka 窄体（字身窄、笔头圆、笔画均匀）。同一个字体栈里 Fredoka 在前、站酷在后，Fredoka 只有拉丁字符，所以中英混排的标题会自动各用各的字。站酷只有一个字重，关掉 font-synthesis 防止浏览器伪加粗。英文正文用 Archivo，避免中文字体把撇号渲染成全角。
5. **长度和格式**：英文通常长 1.5 到 2 倍，标签、按钮、卡片都不定宽，标题字号分语言调；日期用 9 Oct 2026，价格统一 £。
6. **规则不变**：两种语言都过 `rating-guard`；AI 图标签为"AI 示意图 / AI illustration"（与现有 `src/shared/i18n.ts` 一致）。

**需新增**：标准菜名表加拼音字段；`src/shared/i18n.ts` 里补齐新模块的两套文案。

## 12. PC 端

- **内容宽 1200**，12 栏。首页首屏左右分：左边搜索、场景入口、到站屏，右边是全部在营业店的地图。
- **详情页主栏加侧栏**：店铺页、菜品页、专题页的主栏读内容，右侧栏（360 至 470px）放地图和操作，随滚动固定。
- **宽版组件**：线路图把线路名和店数标在线上；原话墙四栏；菜品页用价格表（价格、店、区域、类型、来源），没有评分列；店铺页菜单左侧分类导航、右侧两栏。
- **地图**：项目已经在用 MapLibre，正式版用真实底图；mock 里的街道和公园是手画示意，只有店铺坐标是真的。
- **断点**：1200 以上双栏；768 至 1199 侧栏下沉到正文后；768 以下用手机版。

## 13. 用户注册和个人功能（暂不做）

决定：**不做用户注册，就不做任何和用户个人相关的功能**。以下功能已从 mock 和开发计划里移除，以后和注册一起整体考虑：

- 去过 / 想吃清单、干饭卡、徽章、"我的线路"
- 个人分享海报、年度干饭报告
- 首拍署名、点亮伦敦个人榜单、学校认证和学校对抗
- 提醒（想吃的店有变化、学校周边新店、"有了告诉我"）
- 认领凭证、备份链接和二维码导出

将来考虑注册时要一起想清楚的几点：

1. **初衷**：网站现在不保存任何关于读者的信息（隐私页的承诺）。注册意味着保存邮箱和个人记录，主角也会从店和来源扩展到用户，这是定位上的决定。如果做，要把边界写进 AGENTS.md：注册永远可选，看内容不需要账户；只存必要信息、随时可删；个人数据不出现在店铺页、不汇总成任何统计；只有本人同意才署名（需要修改铁律 23）。
2. **注册前的匿名贡献**：现在访客上传的照片、推荐的店都记作同一个"访客"，没有凭证。在注册上线之前提交的这些贡献，以后无法关联到任何账户。
3. **只存本机不够可靠**：iPhone Safari 会删除 7 天没访问过的网站存在本机的数据，微信内置浏览器和 Safari 的存储也是分开的。所以个人记录要可靠，就需要账户。
4. **最值得做的注册理由**：跨设备同步、提醒、首拍署名、学校认证、年度报告。登录方式优先邮箱一键登录加 Apple / Google；微信登录需要开放平台资质。
5. **始终不做**：用户点评和打分、"想吃人数"这类公开的人气统计。
